# Руководство по тестированию (HR Platform)

Этот документ описывает, как мы тестируем наш проект.

## 1. Пирамида тестирования в нашем проекте

Мы используем три уровня тестов. Не пытайтесь покрыть 100% кода, покрывайте **критическую логику**.

1.  **Unit-тесты (Модульные)**
    *   *Что проверяют:* Бизнес-логику внутри Сервисов (расчеты, проверки условий, валидации).
    *   *Инструменты:* JUnit 5, Mockito, AssertJ.
    *   *Особенность:* Работают без БД и без Spring-контекста. Быстрые.
2.  **Интеграционные тесты**
    *   *Что проверяют:* Связку Controller -> Service -> Repository -> БД. Реальные HTTP-запросы и ответы.
    *   *Инструменты:* `@SpringBootTest`, `MockMvc`, H2 Database.
    *   *Особенность:* Поднимают контекст Spring. Проверяют, что JSON парсится, валидация работает, статусы возвращаются правильные.
3.  **Ручное тестирование (Postman)**
    *   *Что проверяют:* Граничные случаи (Edge Cases), и общую работоспособность перед деплоем.

## 2. Архитектура тестовых файлов

Тесты лежат в `src/test/java` и **зеркалируют** структуру основного кода.
*   Если тестируем `AuthService.java` -> создаем `AuthServiceTest.java` в той же папке.
*   Для интеграционных тестов используем суффикс `IntegrationTest` (например, `AuthIntegrationTest.java`).

## 3. Правила написания Unit-тестов

*   **Название теста:** Должно отвечать на вопрос "Что тестируем и при каких условиях?".
    *   *Плохо:* `test1()`, `testAuth()`.
    *   *Хорошо:* `authenticateUser_ShouldThrowException_WhenPasswordIsWrong()`.
*   **Структура (Паттерн AAA):**
    * **Arrange (Given):** Подготовка данных и моков (`when(...).thenReturn(...)`).
    * **Act (When):** Вызов тестируемого метода.
    * **Assert (Then):** Проверка результата (`assertThat(...)`, `verify(...)`).
*   **Моки (Mockito):** Все внешние зависимости (репозитории, другие сервисы) должны быть замоканы. Тестируем *только* логику текущего класса.

## 4. Правила написания Интеграционных тестов

*   **Аннотации:** Используем `@SpringBootTest` + `@AutoConfigureMockMvc` + `@Transactional` (чтобы откатывать изменения в БД после каждого теста).
*   **Что проверяем:** HTTP-статусы (200, 400, 401, 404), наличие полей в JSON (`jsonPath`), работу `GlobalExceptionHandler` (чтобы при ошибке не вылетал 500, а возвращался красивый JSON).
*   **База данных:** Для тестов используется H2 (в памяти). Настройки лежат в `src/test/resources/application-test.yml`.

## 5. Метрики процентов покрытия

В итоге тесты должны покрывать от 50% по всему проекту и от 80% по сервисному слою 

## 6. Как запустить тесты?

*   В IntelliJ IDEA: Нажать зеленую стрелочку рядом с классом/методом.
*   Через консоль Maven: `mvn test` (запускает все тесты).
*   Проверить покрытие: Run -> Run '...' with Coverage.
